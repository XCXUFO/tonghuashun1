# AI 使用与人工验证记录

日期：2026-10-21。该记录描述本次开发已发生的工作，不包含尚未进行的候选人访谈或用户实验。

## 工具分工

Codex 用于题目拆解、页面与接口实现、构造样本、测试用例、文档。开发者通过本地运行、浏览器操作和自动化测试验证实际行为。产品内的 DeepSeek 用于语义审查与修订草稿，已完成真实调用，记录见 TESTING.md；配置密钥不等于调用成功。

## 设计修正

1. 最初把“没有金融数据权限”理解为只能使用样本。用户指出题目附有数据渠道后，重新读取扶摇全文与 iFinD 指南，确认扶摇 REST 接口与 iFinD 登录后试用入口，并实现扶摇适配。
2. 没有把 HTTP 200 当成数据调用成功。依据官方契约增加业务 code 校验，并加入 2003 权限失败等测试。
3. 没有让“规则未命中”自动变成高质量回答。规则、数值、语义、人工复核分别记录，语义未评测保留未评测状态。
4. 原始数值比较增加了单位家族、显式财务报告期、时间有效性和来源冲突检查，避免错误比对。
5. 用户反馈只决定复核优先级；不把点踩、点赞直接计入事实正确率。
6. 合规规则补充了否定语义与混合句测试，避免“不能保证收益，但一定会涨”逃过检查。
7. 修订回答不直接覆盖原版本，另存为新版本后重新检查，保留回归依据。
8. 真实调用发现模型把行情时间戳误放入财务 period。补充了字段语义约束，并在另存草稿时依据原始证据规范化行情断言，增加两项回归测试。
9. 在脱敏前记录隐私命中标记，使敏感原文不进入持久化记录，同时保留风险线索。

## 验证方法

自动化测试核对字段计算与失败状态，浏览器验证主链路、复核持久化和交互可用性。验证结果与真实外部服务调用状态单独记录在 TESTING.md。预置回答实验只展示回归方法，不宣称模型能力提升。

## 候选人应补充

提交前用自己的话说明取舍与接受的修改；添加本人实际操作、纠错与验证证据，避免把 AI 生成的说明当成亲自完成的用户研究。

## 交付补充验证（2026-10-21 至 22 日）

Codex 新增可操作的“现场修订 Prompt 对照”：同一问题、原回答、画像、证据、评测时点，分别调用两个 Prompt；记录实际返回模型、请求编号和修订稿复评。另用本地验收脚本完成 3 题 × 2 Prompt 的 6 次实际调用，匿名构造输入、真实 API 调用，原始证据见 EVIDENCE.md。未把预置对照或小样本结果写成统计显著提升。

新增模型无密钥、无效输入、HTTP 错误、超时、无效 JSON/越界评分、输入脱敏与注入角色隔离、输出脱敏测试。把无效输入、超时和无效返回分开显示，防止失败被当作正常语义结论。

检查导出时发现：对整个 JSON 文本执行隐私替换可能误伤形似手机号的大额财务数字。改为递归只处理字符串值，数值字段保持原值和类型，并增加回归测试。当前共 35 项离线测试通过。

实际实验保留了 QA-004 的潜在关键词误报与策略措辞边界，不替候选人作已合规结论。当前人工结论仍需要本人补充，见 CANDIDATE_CHECKLIST.md。生产线上 iFinD 的 530 与本地成功分别陈述，根因未确认。
