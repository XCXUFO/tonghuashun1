# AgentLens 产品主链路与设计理由

## 产品定位

目标用户是投资 Agent 的产品经理、模型运营和质量审查人员。目标任务是发现不可信回答、核对证据、确认原因，并验证修改效果。

这是一项待通过实际用户使用验证的产品假设，尚未进行正式用户访谈或生产效果实验。

主链路：匿名问答与版本 → 按意图检查 → 原始证据核验 → 人工确认与归因 → 新版本回答 → 同组样本回归 → 保留问题案例继续检查。

## 1. 接入问题、回答和产生条件

问答样本同时记录匿名画像、热点上下文、模型 / Prompt / 数据版本，以及证据来源、数据时点、获取时点、单位与报告期。只保存一段回答，无法确定错误是否来自旧数据、错误字段或生成过程，也无法复现版本差异。

当前入口支持手动创建与 JSON 导入。尚未自动接入生产 Agent 的问答日志。

## 2. 不同意图采用不同标准

行情查询优先检查标的、数值与时点；财务解读还必须确认报告期与单位；知识解释检查是否回答核心问题；热点分析区分权威确认与传闻；个性化问答检查表达适配和事实是否漂移。

意图由样本提供。主题词检查只是初筛线索，不能代替完整语义判断。

## 3. 将计算、证据、语义和最终判断分工

规则引擎负责数值比较、单位换算、时间约束、来源冲突与部分风险规则。扶摇 / iFinD 提供实际可调用的原始数据。DeepSeek 辅助审查回答相关性、上下文使用与解释适配，并生成修订草稿。人工复核确认问题、纠正误报、补充证据并决定改进方向。

模型输出的意见不能覆盖确定性核验结果。模型调用失败不计为语义评测成功，未发现规则问题也不等于整体回答合格。

## 4. 通过证据解释问题

构造示例：同一标的与快照下，回答声称成交价 1380 元，而原始 last_price 字段为 1280 元。平台标出矛盾，并展示字段、单位、数据时间与请求编号，供人工确认。

若数据调用失败，则是证据不足；若来源时点不同，则不能作为同一快照直接比较；若财务断言缺少报告期，则拒绝任意匹配某一年度。无法核验与已证实错误需要分别处理。

## 5. 人工复核与反馈

人工结论有确认问题、规则误报、待补证据和人工通过四类，单独保存，不覆盖自动线索。用户点踩或投诉用于确定复核优先级，不直接计为金融事实错误。

例如，“不能保证收益”可能被简单关键词规则误判。人工确认后，应修改规则并保留误报样本，检查新规则是否又漏掉真正的收益承诺。

当前“高风险拦截”是评测状态标记，尚未接入真实 Agent 的实时发布阻断。

## 6. 归因指向具体改进

同样是数字错误，可能是数据过期、标的或报告期选择错误、生成引用错误，也可能是评测规则误报。对应措施分别是刷新数据、修正参数与选择逻辑、增强引用及输出校验、修订评测规则。

单凭最终回答不能自动确定底层代码根因；当前由人工根据证据记录归因，未接入完整生产执行轨迹。

## 7. 修订必须另存并复评

DeepSeek 修订草稿另存为新的回答版本，保留原版本，随后重新执行规则与数字检查。真实调用中曾发现模型把行情时间戳填入财务报告期，已补充字段约束、规范化处理与回归测试；修订文字看起来合理，仍需要验证结构化信息。

当前修订的是评测候选回答。真实 Agent 的 Prompt、数据流程与代码需要人工修改，并把新输出带回平台验证。没有自动修改或发布生产 Prompt。

## 8. 同组样本回归

比较时固定问题、画像、数据与评测规则，分开观察模型、Prompt 和数据版本变化。若同时改变多个因素，不能把改善归因于其中某一个因素。

数字一致率与断言覆盖率一起观察：从 10 条断言中 8 条一致，变为只保留 1 条且一致，不能仅凭一致率从 80% 升到 100% 就认定产品进步。人工复核覆盖率也不是人工正确率。

内置两版回答是预置对照，用于展示回归方法，不证明 Prompt 的因果改进效果。现场模型生成的修订版本可以单独检查与对比。

## 个性化边界

术语深浅、解释结构、篇幅和风险提示可以随画像变化。客观数字、报告期、来源、数据时间、事件真伪与风险事实不能变化。匿名经验和风险偏好不作为交易授权或适当性结论。

双画像示例固定同一份证据：新手回答 1280 元，熟练用户回答 1320 元；表达差异可以接受，后者与原始字段的矛盾必须被识别。

## 两种闭环与首版边界

回答级闭环：发现问题 → 核对证据 → 人工确认 → 形成候选回答 → 重新检查 → 在同组样本中比较。当前版本可人工触发完成。

系统级持续治理：自动采集生产日志 → 定时评测 → 组织复核 → 修改实际 Agent → 发布并监测。当前版本尚未完成自动日志接入、后台定时任务、多人协作和自动发布。

审查记录保存在当前浏览器，支持导出。换设备需要迁移记录，没有共享审查数据库。

## 页面为什么这样分

质量概览用于排优先级；评测工作台用于检查单条回答与证据；版本实验用于验证变化；个性化治理用于检查事实边界；规则与数据用于说明标准和验证真实连接。

页面围绕审查动作分工，使用户从异常发现进入具体问题，确认依据后能够继续处理和验证。
